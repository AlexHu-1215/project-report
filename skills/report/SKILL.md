# Project Report

让用户打开 `report/index.html` 就能知道实验做到哪了、结果如何，以及对应的设置与实现。

## 启用范围

用户显式调用后，在当前会话持续记录，直到用户要求停止。将启用状态保留在会话摘要中。每个新会话由用户重新启用。只查看历史报告时直接打开页面。

项目原则保存在项目根目录 `AGENTS.md`，长期适用。实验的进度采集随已登记的实验进程运行，报告整理在本会话进行。

## 初始化与打开

先读取项目现有的 `AGENTS.md`。首次安装到项目或首次启用时，合并 [项目原则模板](assets/project-principles.md)，保留现有约定。初始化脚本补齐缺失原则、会话约定和报告目录。

下方 `SKILL_DIR` 表示本 `SKILL.md` 所在目录，`PROJECT` 表示用户选定的项目根目录：

```sh
python3 "$SKILL_DIR/scripts/report.py" init --project "$PROJECT"
python3 "$SKILL_DIR/scripts/report.py" serve --project "$PROJECT" --port 8765
```

服务仅监听 `127.0.0.1`。打开输出的地址，给用户报告入口。已在当前项目运行的服务直接复用。服务跟随启动它的进程存活。

## 一页一个阶段，一行一次运行

- 一个阶段性研究问题对应一个稳定的页面，同组实验集中在该页的主表。
- 每次运行分配可读 ID，例如 `exp-001`。同一次运行持续更新同一行；复跑新增运行 ID，并保留原记录。
- 新建阶段时读取 [数据与采集约定](references/recording.md)，创建同名的阶段 JSON 和 Markdown，随后执行 `build`。
- 页面按“当前结论 → 实验表 → 关键图表 → 解释与下一步”组织。完整配置、命令、实现、性能与产物放在实验行的展开详情。
- 共用设置写在阶段元信息中，每行突出差异；每次运行保留自己的完整实际配置。

## 实验记录流程

1. 启动前建立记录，保存实际命令、配置、关键改动和对应文件/函数。把采集调用接入本次实验已有的进度和评估输出。
2. 训练或评估期间由实验进程调用 `Run.update()`，更新真实 step、指标与采集时间。按评估节点或适当的时间间隔采集。
3. 实验正常结束调用 `Run.finish()`，登记最终指标和状态。失败任务保存实际错误与日志位置；可由调度端或本会话更新为 `failed`。
4. 取得新结果后，在阶段 Markdown 和相关实验的 `comment` 中补充简短解释。单独更新 `analysis_at`，执行 `build` 保存可离线浏览的快照。

已有日志可通过一个针对实际格式的读取步骤写入相同记录；读取到哪一步就记录哪一步。运行状态与结论依据分别记录。运行中指标标注为当前值，已完成实验的最终指标用于完成结果比较。

后台运行的实验携带采集调用或既有日志读取进程。普通网页刷新读取已采集的数据。将已接入的采集方式、最近进度和更新时间告诉用户。

## 写作与性能

- 用几句话说明问题、发现、证据和下一步，细节按需展开。将实测结果、推断和待验证想法明确标注。
- 执行 [项目原则模板](assets/project-principles.md) 中的精简实现、GPU 优先、根因修复、肯定表达与训练性能要求。
- 训练记录包含 GPU、显存、吞吐、micro-batch、梯度累积、全局 batch 和并发数。通过实际设备与资源数据确认 GPU 使用。
- 保持训练设定时，增大 micro-batch 配合调整梯度累积；全局 batch 的变动作为实验变量记录。用实际吞吐衡量 infra 优化效果。

## 完成与演示

阶段结束时核对表格、设置、证据和结论，并实际打开页面查看展示效果。最终回复给出阶段页面和当前结论。

用户明确要求演示时，可运行 `demo` 创建标注为演示数据的示例阶段。该命令写入示例记录与页面。真实实验从独立阶段开始。
