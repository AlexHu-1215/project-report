# Project Report

让用户打开报告就能知道实验做到哪了、结果如何，以及对应的设置与实现。

## 启用范围

用户显式调用后，在当前会话持续记录，直到用户要求停止。将启用状态保留在会话摘要中。每个新会话由用户重新启用。只查看历史报告时直接打开页面。

项目原则保存在项目根目录 `AGENTS.md`，长期适用。已登记实验的采集与进程监测随启动器运行，报告解释在本会话整理。

## 初始化与打开

先读取项目现有的 `AGENTS.md`。首次启用时，合并 [项目原则模板](assets/project-principles.md)，保留现有约定。`SKILL_DIR` 表示本 `SKILL.md` 所在目录，`PROJECT` 表示目标项目根目录：

```sh
python3 "$SKILL_DIR/scripts/report.py" init --project "$PROJECT"
python3 "$SKILL_DIR/scripts/report.py" serve --project "$PROJECT" --port 8765
```

服务监听 `127.0.0.1`。打开输出的地址，给用户报告入口。已有服务直接复用；更新报告程序后重新启动服务。实时进度通过本地服务查看，HTML 文件保存最近一次生成的快照。

## 一页一个阶段，一行一次运行

- 一个阶段性研究问题对应一个稳定页面，同组实验集中在主表。
- 先读 [记录与启动约定](references/recording.md)，由 Codex 根据实际任务准备实验描述。`run --spec` 一次完成登记和启动；`new --spec` 登记待运行实验，`start --stage --run` 启动该行。复跑分配新运行 ID。
- 登记时保存计划配置和实现；启动时重新采集配置文件和关键代码。程序通过 `configure()` 登记解析默认值和覆盖项后的实际配置。表格自动突出相对基线的设置变化。
- 页面按“当前结论 → 实验表 → 关键图表 → 解释与下一步”组织，完整设置、命令、实现、性能与产物按需展开。

## 实验记录流程

1. 训练主 rank 获取 `Run.from_env()`，调用 `configure(actual_config)` 保存实际生效的完整配置。在现有日志与评估回调中调用 `update()`；异步评估填写 `metric_step`。
2. 用启动器执行实际前台命令，等待训练或调度作业结束。启动器登记主机、进程、退出码和日志；心跳中断后页面显示“待确认”。
3. 最终评估完成后调用 `finalize(step=..., metrics=...)`，提交阶段定义的最终指标。提前停止的实验同样明确提交最终评估。进程结束和最终评估分别记录，最终比较使用两者均已就绪的结果。
4. 训练进程向事件文件追加采样，启动器维护状态，Codex 用 `annotate` 写独立解释。通过 `conclude --stage ... --summary ... --runs ...` 保存阶段结论及其依据，随后补充几句话解释与下一步。新评估出现后，页面提示结论待更新。

既有日志可按实际格式接入采集。告知用户当前采集方式、监测方式和最近采集时间。远端训练时让启动器和记录文件位于训练环境，通过 SSH 端口转发查看报告。

## 写作与性能

- 清楚说明问题、发现、证据和下一步。实测结果、推断和待验证想法明确标注，结论关联支持它的实验行。
- 执行 [项目原则模板](assets/project-principles.md) 中的精简实现、GPU 优先、根因修复、肯定表达与训练性能要求。
- 训练记录包含实际 GPU、显存、吞吐、micro-batch、梯度累积、全局 batch 和并发数。
- 保持训练设定时，增大 micro-batch 配合调整梯度累积；全局 batch 的变动作为实验变量记录。用实际吞吐衡量 infra 优化效果。

## 完成与演示

阶段结束时核对表格、实际设置、最终评估和结论依据，打开页面查看展示效果。最终回复给出阶段页面与当前结论。

用户明确要求演示时运行 `demo`，创建标注为示例数据的阶段。真实实验从独立阶段开始。仓库中的 `examples/tiny-regression/` 可用于验证实际训练与报告的完整流程，训练额外需要 PyTorch。
