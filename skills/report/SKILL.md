# Project Report

让用户打开报告就能知道实验做到哪了、结果如何，以及对应的设置与实现。

## 启用范围

用户显式调用后，在当前会话持续记录，直到用户要求停止。将启用状态保留在会话摘要中。每个新会话由用户重新启用。只查看历史报告时直接打开页面。

项目原则保存在项目根目录 `AGENTS.md`，长期适用。已登记实验的采集与进程监测随启动器运行，报告解释在本会话整理。

## 初始化与打开

先读取项目现有的 `AGENTS.md`。首次启用时，合并 [项目原则模板](assets/project-principles.md)，保留现有约定。`SKILL_DIR` 表示本 `SKILL.md` 所在目录，`PROJECT` 表示目标项目根目录：

```sh
python3 "$SKILL_DIR/scripts/report.py" init --project "$PROJECT"
python3 "$SKILL_DIR/scripts/report.py" serve --project "$PROJECT" --port 8765
```

服务监听 `127.0.0.1`。打开输出的地址，给用户报告入口。已在当前项目运行的服务直接复用。实时进度通过本地服务查看；直接打开 HTML 可查看最近一次生成的快照。

## 一页一个阶段，一行一次运行

- 一个阶段性研究问题对应一个稳定页面，同组实验集中在主表。
- 使用统一入口创建阶段、运行 ID、配置与实现快照。先读 [记录与启动约定](references/recording.md)，由 Codex 根据当前任务准备一份实验描述。
- `run --spec` 一次完成登记和启动；`new --spec` 登记待运行实验，`start --stage --run` 启动该行。复跑使用新运行 ID。
- 共用设置写在阶段元信息中，每行突出差异，每次运行保存实际完整配置。关键实现保存文件、行号与当时的代码内容。
- 页面按“当前结论 → 实验表 → 关键图表 → 解释与下一步”组织。完整设置、命令、实现、性能与产物放在行内详情。

## 实验记录流程

1. 把 `Run.from_env().update()` 接入已有进度和评估输出，按真实评估节点采集。多进程训练由主 rank 写入记录。指标携带实际评估 step；异步评估使用 `metric_step`。
2. 用统一启动器执行实际前台训练或评估命令，保存输出日志。启动器登记主机、进程、退出码并自动收尾；通过心跳识别监测中断，页面显示“待确认”。调度任务让启动器等待实际作业结束。
3. 训练进程只更新采样文件；启动器只更新状态文件；Codex 用 `annotate` 写独立解释文件。更新解释后生成页面快照。
4. 根据证据补充阶段结论和下一步。结果比较使用已完成实验与已完成基线，逐项核对指标及评估设置。运行期间的指标按其采样 step 阅读。

既有实验可通过针对实际日志格式的采集步骤接入；状态由实际进程或调度系统确认。告知用户当前采集方式、监测方式与最近采集时间。远端训练时让启动器和记录文件位于训练环境，通过 SSH 端口转发查看报告。

## 写作与性能

- 用几句话说明问题、发现、证据和下一步。实测结果、推断和待验证想法明确标注。
- 执行 [项目原则模板](assets/project-principles.md) 中的精简实现、GPU 优先、根因修复、肯定表达与训练性能要求。
- 训练记录包含实际 GPU、显存、吞吐、micro-batch、梯度累积、全局 batch 和并发数。
- 保持训练设定时，增大 micro-batch 配合调整梯度累积；全局 batch 的变动作为实验变量记录。用实际吞吐衡量 infra 优化效果。

## 完成与演示

阶段结束时核对表格、设置、证据和结论，并打开页面查看展示效果。最终回复给出阶段页面和当前结论。

用户明确要求演示时，运行 `demo` 创建标注为示例数据的阶段。真实实验从独立阶段开始。
