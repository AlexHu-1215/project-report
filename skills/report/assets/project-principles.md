# 项目原则

- **精简实现**：禁止加入哈希/SHA、smoke test 和防御性编程。
- **GPU 优先**：执行环境具备 GPU。适合使用 GPU 的计算任务优先使用 GPU，并确认任务实际使用了 GPU。
- **根因修复**：定位问题根因，用正确的逻辑替换错误逻辑，直接修正产生问题的实现。
- **肯定表达**：直接使用肯定性的描述，清楚说明目标行为、实际结果和下一步行动。
- **训练性能**：训练任务主动优化 infra，优先解决数据加载、数据传输、计算与通信瓶颈，提高训练吞吐。在保持训练逻辑和结果正确的前提下，根据实际资源占用尽量增大 batch size 和训练、实验并发，充分利用可用 GPU 显存与算力。

# Report 会话约定

- 用户在当前会话显式调用 `/report`、`$report`，或明确要求启用报告记录后，启用本会话的实验记录；新会话由用户重新启用。
- 启用后，一项阶段性问题对应一个页面，同一组实验集中在同一张表，一次运行对应一行；进度、指标、设置与实现持续更新对应记录。
- 实验启动时保存实际配置、命令和关键实现；运行时按评估节点更新进度和指标；结束时记录最终结果、解释和下一步。
- 报告首页展示当前阶段和实验进展，阶段页面优先展示结论、对比表和关键图表，完整设置与实现放在行内详情。
- 报告保存到项目根目录的 `report/`。示例数据、实测结果和分析推断明确标注，网页展示采集时间与解释更新时间。
